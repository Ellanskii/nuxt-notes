# Заметки

SPA для заметок со списками задач. Nuxt 4, Composition API, TypeScript strict, Pinia, SCSS.
Данные хранятся в localStorage, серверной части нет.

## Запуск

```bash
pnpm install
pnpm dev          # http://localhost:3000
```

Проверки:

```bash
pnpm test         # unit-тесты
pnpm test:coverage
pnpm typecheck
pnpm lint         # eslint + stylelint
```

Docker:

```bash
docker compose up --build     # на старых установках: docker-compose up --build
```

Приложение поднимется на http://localhost:3000. В CI (`.github/workflows/ci.yml`) прогоняются
линтеры, типы, тесты с порогом покрытия и сборка образа.

## Структура

```
app/
  lib/           чистая логика без Nuxt, вся под тестами
    patch.ts     описание одного изменения заметки
    history.ts   движок undo/redo
    shortcut.ts  правило разбора Ctrl+Z
    storage.ts   адаптер localStorage со схемой и миграциями
    merge.ts     слияние состояния вкладок
  stores/        Pinia-стор заметок
  composables/   редактор, модалки, focus-trap, тема
  components/    base/ icon/ modal/ note/ editor/
  pages/         index.vue и notes/[id].vue
i18n/locales/    ru.json, en.json
tests/unit/      11 файлов, 100 тестов
```

## Решения

**История — патчи, а не снапшоты.** Запись хранит только изменившееся поле
(`{ t: 'todo-done', id, from, to }`), поэтому 50 шагов весят килобайты независимо от размера
списка. Хранить 50 копий заметки запрещено условием, но и без запрета это плохо масштабируется.
Движок в `app/lib/history.ts` не знает ни про Vue, ни про таймеры — время передаётся параметром,
поэтому тесты детерминированы. Помимо точечных кейсов есть фаззинг: 200 случайных операций с
фиксированным сидом, откат до упора должен дать исходное состояние, повтор — финальное.

**Непрерывный ввод — одна запись.** Ввод в одно поле копится в `pending` и фиксируется по blur,
по паузе 600 мс, при переключении на другое поле и перед любой атомарной операцией. Ввод,
вернувший поле к исходному значению, записи не создаёт. Отметка чекбокса, добавление и удаление
пункта пишутся сразу и по отдельности.

**Ctrl+Z и нативная отмена.** Пока в поле идёт ввод и фокус из него не уходил, приоритет у
браузера — иначе посимвольная отмена внутри поля стала бы недоступна. Как только фокус ушёл или в
текущей фокус-сессии ничего не набрано, Ctrl+Z отменяет изменение заметки. Под открытой модалкой
хоткей не работает, наборная сессия IME пропускается. Решение вынесено в чистый предикат
`resolveUndoIntent` и покрыто таблицей тестов. «Грязность» поля отслеживается по событию `input`,
а не по клавиатуре, поэтому вставка, drag-and-drop, отмена из контекстного меню и коммит IME
учитываются наравне с хоткеем, а накопленный патч всегда описывает итоговое изменение поля.

**Запись в хранилище — пачкой.** Стор дебаунсит запись на 700 мс и сбрасывает её принудительно на
`pagehide` и уходе вкладки в фон. Данные лежат в конверте с номером схемы; версия из будущего не
перезаписывается, битый JSON не роняет приложение, недоступный localStorage подменяется
memory-адаптером. Миграция v0 → v1 (пункты были строками) реально работает и проверена тестом.

**Вкладки не затирают друг друга.** Запись целого массива по принципу «кто последний, тот и прав»
стирала бы чужие заметки, поэтому стор ведёт журнал локальных изменений и удалений, а перед
записью перечитывает актуальный слепок и накладывает свои правки поверх. Событие `storage`
проходит через то же слияние. Рассматривался вариант с ключом на заметку — он убирает гонку
структурно, но требует отдельный индексный ключ, и для двух страниц это лишняя сложность.

**Черновики.** Незасохранённое редактирование пишется под отдельным ключом на каждую заметку
(`nuxt-notes:draft:<id>`), поэтому брошенный черновик одной заметки не затирается открытием
другой. При возврате предлагается восстановить. История при этом пустая: по условию она живёт в
рамках сессии редактирования, а восстановленный черновик — новая точка отсчёта.

**Без VueUse.** Формально условие его не запрещает, но `useRefHistory` и `useStorage` — это ровно
библиотеки undo/redo и автосинхронизации стора с хранилищем из списка запретов, а
`useFocusTrap` из `@vueuse/integrations` подрывает требование собственных модальных окон. Без них
выгода околонулевая: дебаунс, слушатели и focus-trap — около сорока строк.

**i18n.** Локализации в задании нет; строки вынесены в `i18n/locales`, чтобы не размазывать текст
по шаблонам, а переключатель языка — побочный эффект. Стратегия `no_prefix`: маршрутов
по-прежнему два, префиксов локали в URL нет.

**Тема — своя.** Светлая, тёмная и системная на CSS-переменных с классом на `<html>`. Инлайн-скрипт
в `<head>` выставляет класс до первой отрисовки, поэтому нет вспышки. Готовый модуль не
подключён: он пишет собственный ключ в localStorage и потребовал бы оговорки на ровном месте.

**Тесты.** Конфиг берётся из `@nuxt/test-utils`, но окружение по умолчанию — `happy-dom`, а не
`nuxt`: ядро и стор от рантайма Nuxt не зависят (хранилище инжектится параметром), а подъём
инстанса стоил бы секунд на каждый файл. Полное окружение при необходимости включается пофайлово
докблоком `// @vitest-environment nuxt` — так проверяются макет, модалка подтверждения и
страница редактирования. Основной объём тестов — на истории изменений и сторе, как требует задание.

## Поведение в спорных случаях

- Прямая ссылка на несуществующую заметку — экран «Заметка не найдена» со ссылкой к списку.
- Пустое название сохраняется, в списке показывается как «Без названия».
- Пустые пункты не сохраняются; пока они есть, под списком висит подсказка.
- Заметку удалили в другой вкладке во время редактирования — приложение предлагает уйти к списку
  или сохранить правки как новую заметку.
- Длина названия ограничена 200 символами, текста пункта — 500.

## Что не реализовано и почему

- Нет слияния при одновременном редактировании **одной** заметки в двух вкладках: побеждает та,
  что сохранила последней. Для этого нужен CRDT или пооперационная синхронизация — это заметно
  больше объёма задания.
- Нет виртуализации списка: на разумном числе заметок она не окупается.
- Нет e2e-тестов. Логика разбора Ctrl+Z покрыта unit-тестами, но поведение нативной отмены в
  полях различается между браузерами и проверялось вручную.
